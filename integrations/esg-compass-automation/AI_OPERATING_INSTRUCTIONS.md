# AI 操作说明

你负责运行并维护 ESG Compass 自动追踪工作流。默认不需要向用户请求额外确认。

## 每次运行

1. 在包目录运行 `python run_workflow.py`。
2. 读取 `out/ai_payload.json`。
3. 仅使用其中 `items` 的标题、摘要、推荐理由、评分、来源和链接生成中文简报。
4. 保存或发布到已经授权的个人工作平台。
5. 如果平台发布失败，保留输出文件并返回非零退出状态。

## 内容规则

- 使用第三方编辑视角，禁止“我、我们、本文、本刊、笔者”等表达。
- 不得编造接口未提供的事实、日期、数字、影响或因果关系。
- 精选内容必须突出推荐理由；非精选内容不得生成推荐理由。
- 每条内容必须保留原文链接。
- 同类事件优先合并叙述，但不得合并不同主体或不同时间发生的事实。
- 新闻摘要保持完整成句，单条首页摘要不超过 300 个中文字符。
- 优先呈现政策、监管、披露、供应链、气候、自然、人权和可持续金融的实质变化。

## 自动化约束

- 每 30 至 60 分钟运行一次即可。
- 必须保留 `state/state.json`，不要每轮清空。
- 使用事件 ID、发布时间和评分组成的处理键去重。
- API 请求失败时最多重试 3 次，使用指数退避。
- API 连续失败时保留上一轮输出和游标，不要回退状态。
- 使用已经配置好的平台连接器发送结果；缺少凭据时应停止并明确报告，不要在运行中向用户提问。
- 不修改 ESG Compass 仓库、不启用新信源、不修改 API。

## 工作平台建议格式

```text
ESG Compass 更新｜YYYY-MM-DD HH:mm

今日重点
1. 标题｜地区｜类型｜评分
   事件摘要
   推荐理由（仅精选）
   原文

持续跟踪
- 标题｜为什么值得继续关注｜原文
```

## 失败处理

- HTTP 429：等待 `Retry-After` 或至少 60 秒后重试。
- HTTP 5xx：指数退避后重试。
- 单条字段缺失：跳过该条并写入运行日志，不要猜测。
- 平台发布失败：保留文件，下一轮不得重复发送已成功发送的内容。
