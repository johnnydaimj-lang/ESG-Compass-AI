# ESG Compass v2 产品需求说明

文档版本：2.2.0
基线日期：2026-11-17
适用目录：`ESG Compass_v2`  
实现原则：公开页面与公开 API 只读取发布快照，不从历史草稿或旧字段临时拼接。

## 1. 产品定义

### 1.1 产品目标

ESG Compass 是面向持续跟踪全球 ESG 变化的专业信息产品。它把官方政策、行业动态、机构观点、学术研究与评级动态归一为可浏览、可检索、可审核的中文内容，并通过独立信源交叉验证形成故事、事件与热点。

核心目标是让用户在三分钟内回答三个问题：

1. 过去一段时间全球 ESG 发生了什么。
2. 哪些变化值得优先关注，依据是什么。
3. 事件属于哪个议题、地区、专区，以及原文在哪里。
4. 重要企业正在采取哪些 ESG 行动，或因哪些 ESG 问题遭受执法、争议与实际经营影响。

### 1.2 目标用户

- 企业 ESG、可持续发展和合规团队。
- ESG 咨询、研究和投资分析人员。
- 需要快速扫描政策与披露变化的业务负责人。
- 通过受控内容 API 接入已发布数据的内部系统。

### 1.3 当前产品边界

- 公开前台：首页时间轴、事件详情、ESG 专区。
- 运营后台：运营看板、内容审阅、筛选规则、信源治理、热点、月度洞察、专区、产品说明。
- 管理能力：管理员登录、运营页面保护、运营 API 鉴权、私有内容 API。
- 数据能力：固定信源配置、快照/实时采集扩展、预筛、双评分、结构化理解、聚簇、热度、发布快照。
- 企业事件作为“行业”内容的一部分，覆盖具体 ESG 行动与企业 ESG 风险事件，不增加独立前台模块。

### 1.4 明确不在当前范围

以下能力不属于 v2 当前产品范围，不得出现在新 PRD、产品地图或导航中：

- 个人工作台。
- 独立知识库页面。
- 面向公众的 AI 问答。
- Agent、Harness 或工作流执行平台。
- 企业自身 ESG 评级升降。
- 企业档案、企业风险预警、企业排行榜和企业趋势统计。
- 指数入选、获奖名单和年鉴。
- Mock 内容。
- 已删除或仅存在于历史版本的功能描述。

## 3. 核心用户流程

### 3.1 公开浏览

1. 用户打开首页，按发布时间从新到旧浏览。
2. 用户可按内容类型或“只看精选”过滤。
3. 用户可按 `YYYY-MM` 回溯历史。
4. 用户进入事件详情，阅读中文标题、摘要、精选理由和影响分析。
5. 用户可跳转原文，并从专区导航进入相关联的事件与法规。

### 3.2 运营审核

1. 流水线将高风险或待补充材料写入审阅队列，不直接公开。
2. 管理员在 `/review` 修改摘要、ESG 议题和重要性。
3. 批准后内容写入发布快照；驳回后从发布快照移除并写入驳回库。
4. 所有决定写入审阅决策记录，供后续规则校准。

### 3.3 发布与消费

1. 采集器产生原始材料，或使用已确认的历史快照。
2. 预筛只允许 `PASS` 与 `UNKNOWN` 继续，`BLOCK` 终止。
3. 每条材料执行两次独立评分。
4. 两次分数均不低于理解底线，且总分不低于两倍信源门槛时入选。
5. 结构化理解生成中文标题、摘要、标签、作者角色和推荐理由。
6. 聚簇按材料 ID 合并故事，按真实信源 ID 统计参与方。
7. 热度按独立信源计算，并写入热点故事。
8. 所有公开出口统一读取 `data/publication` 中的发布快照。

## 4. 功能需求

### FR-01 内容采集

- 支持配置化信源，保留 `id`、名称、URL、类型、内容类型、地区、语言、启用状态和环境变量要求。
- 采集阶段必须保留材料 ID 与信源 ID，二者不得互换。
- 采集器失败必须进入状态记录，不得静默返回空集合。
- 默认快照模式必须可在无网络环境中复现当前发布数据。
- 实时模式只为已实现的适配器调用网络；跳过或失败必须产生 warning。
- 信源可配置有序备用通道；主通道缺少凭据、抓取失败，或在 `fallbackOnEmpty` 开启时返回空结果，流水线应按顺序尝试备用通道。
- 备用通道成功时，`sourceRuns` 必须保留原信源身份并记录 `fallbackUsed=true`、实际通道和降级原因；所有备用通道失败时必须记录尝试原因，不得伪造成功。
- 企业事件信源优先使用监管机构、执法机构、企业官方发布和有编辑审核的专业媒体；新信源必须先验证产出与噪声。

### FR-02 预筛

- `BLOCK`：材料可确认与 ESG 无关，或属于招聘、报名、培训等噪声。
- 周报、日报、Week in Review、本周盘点等周期性多事件汇编不得作为独立事件进入时间线；应回到其中单条事实的原始来源采集。
- `UNKNOWN`：材料信息不足，继续后续流程并保留。
- `PASS`：存在明确 ESG 事实、政策、研究、评级、观点或风险信号。
- 具体企业的 ESG 投资、收购、供应链计划、清洁能源、循环经济、水资源、人权劳工与风险应对行动可进入预筛。
- 具体企业的处罚、调查、诉讼、停工、整改、争议或极端天气经营影响可进入预筛，但必须保留证据阶段。
- 普通融资、并购、产品发布、获奖或业绩新闻不因附带 ESG 表述而自动通过。
- 空标题、空摘要和空正文返回 `UNKNOWN`，不得误判为 `BLOCK`。

### FR-03 双评分与精选

- 每条材料产生两次独立评分，明确输出 0 到 100 的整数。
- 五轴评分包括重要性、新颖度、可信度、共鸣面和可行动性。
- 展示分取两次评分的算术平均值后向下取整。
- 入选条件为：
  `score1 + score2 >= threshold * 2`
  且 `score1 >= understandFloor`
  且 `score2 >= understandFloor`。
- `SIGNAL` 信源只参与热度证据，不进入精选。
- 阈值按 ESG 样本继续校准；当前实现保留 T1=60、T1_5=65、T2=76、统一理解底线 45。

### FR-04 内容理解

- 输出内容类型、作者角色、1 到 6 个标签、推荐理由、中文标题和中文摘要。
- 推荐理由只描述当前材料支持的一层阅读价值，不补写事实。
- 内容类型限定为政策、行业、观点、学术和评级。
- 企业 ESG 行动与企业 ESG 风险事件统一归入“行业”；针对具体企业的处罚和诉讼不得误分为政策。
- 企业事件标题与摘要必须明确企业主体、具体动作或风险及关键规模；未决指控不得写成已证实事实。
- 作者角色限定为主事方、观察者或转述者。

### FR-05 结构化事实

- 至少提取标题、主体、动作、对象和发生日期。
- 结构化结果用于聚簇辅助、事件详情和受控 API。
- 日期无法确定时回退到材料发布日期，不伪造精确日期。

### FR-06 故事聚簇

- `memberIds`、`rootId` 和 `relations[].memberId` 必须引用材料 ID。
- `participants` 必须是材料对应真实信源 ID 的去重集合。
- 关系标签支持 `SAME_OCCURRENCE`、`SAME_STORY`、`UNRELATED`、`ROUNDUP`。
- 近重复阈值参考 0.92，同故事阈值参考 0.60，召回窗口参考 14 天。
- 跨语言、官方原文与媒体报道、同一公告的不同报道应归为同一故事。

### FR-07 热度

- 默认窗口为 48 小时，半衰期为 24 小时。
- 同一独立信源只计一次，取窗口内最新材料。
- 至少 2 个参与方且至少 1 个编辑信源才产生热度。
- 热点故事按热度和最近发布时间排序。

### FR-08 发布快照

`data/publication` 是公开内容的唯一事实源，至少包含：

- `contents.json`
- `stories.json`
- `hotspots.json`
- `status.json`
- `version.json`

公开页面和公开 API 在发布快照不存在时应返回空集或明确状态，不得回退读取旧 `data/contents.json`。旧文件仅作为一次性迁移输入。

### FR-09 运营看板

- 显示最近运行时间、原始量、预筛量、评分量、精选量、故事量与热点量。
- 显示每个已运行信源的状态与产出量。
- 来源状态必须来自 `publication/status.json` 的 `sourceRuns`。
- warning 必须在状态对象构造前收集，确保可持久化。

### FR-10 审阅

- 审阅读写发布快照，不直接修改旧内容库。
- 批准或驳回必须记录 `id`、标题、动作、时间和规则摘要。
- 保存草稿必须保留发布快照的其它字段。

### FR-11 受控内容 API

- 使用 `ESG_API_KEY` Bearer 鉴权。
- 支持分页、内容类型、精选、更新时间和专区过滤。
- 返回中文优先摘要，并标注摘要是否截断。
- 对外响应使用产品语义命名，不使用已删除的 Agent 命名。

### FR-12 安全

- 运营页面和运营 API 必须验证管理员会话。
- 管理会话使用 HMAC 签名、HttpOnly、SameSite=Lax，生产环境启用 Secure。
- 所有 API 路由受 IP 限流保护。
- 公共响应不得包含环境变量、模型密钥或内部脚本输出。

### FR-13 企业事件增强

- 不增加新的顶级导航、企业页面、趋势图表或风险预警。
- 复用现有“行业”内容类型、故事聚簇、AI 评分、公开门槛和精选推荐理由。
- 首期重点包含两类事件：可验证的企业 ESG 行动，以及有可靠证据的企业 ESG 风险事件。
- 验收样本中应纳入事件的确定性预筛与分类命中率应不低于 85%，明显无关企业新闻不得自动进入 `PASS`。
- 同一企业同一事件继续使用现有聚簇去重；公开内容仍必须通过 `isFeedEligible`。
- 公开事件必须有可用的中文标题与中文摘要，摘要长度为 20 至 300 字；翻译或摘要修复失败时保留记录但不公开。

### FR-14 气候风险实验室

#### 问题与目标

企业用户能看到大量气候披露规则和风险事件，却很难把“情景变化”连续理解为“地点暴露—经营影响—财务报表影响”，也无法判断模型结论由哪些输入和假设产生。本功能以独立实验室提供一个可解释的轻量交互器，帮助用户建立因果链并检查参数，而不是提供厂址级预测、保险定价或自动估值。

主要用户为企业 ESG、风险、财务和资产管理人员。核心任务是：选择一个项目地点与风险，理解风险如何影响经营活动、公允价值及其他会计估计，并回到 ESG Compass 的真实事件继续研究。

#### 核心流程（2026-11-18替代原型乘数方案）

1. 选择IPCC、IEA或NGFS体系、版本内路径与观察时间窗。
2. 选择适用风险；IPCC展示物理风险，IEA/NGFS展示转型风险。
3. 阅读影响链，调整停工、贡献毛利、修复或履约碳成本假设。
4. 查看条件敏感性；按需展开项目现状、适应措施、公式和依据。
5. 按风险、类型和时间查看近五年实际影响与应对样本。

#### 功能要求

- 首期位于独立页面 `/climate-lab`，从首页内容类型筛选栏最右侧以单一入口进入，不增加新的顶级导航或独立 Banner。
- 实验室核心问题标题使用“气候风险如何进入财务报表？”，“虚拟项目”仅作为输入对象和用途边界说明，不占用核心标题。
- 每条情景均显示基于官方介绍的简明中文释义、版本和用途；可展开官方英文原文短引、短引译文、原始章节/段落定位、核对日期与完整介绍链接。“ESG Compass适用说明”另行标注，不冒充官方原文；释义不得暗示情景是预测，SSP编号不得解读成温升。切换路径时收起原文详情并保留经营输入。
- 首页入口使用实验烧瓶标识和“进入实验室”文字，用于表达产品除信息聚合外的分析创新能力；入口必须与“全部｜政策｜行业｜观点｜学术｜评级”同栏，避免占用资讯首屏篇幅。
- 旧地址 `/zones/climate-lab` 永久跳转到 `/climate-lab`，避免已有链接失效。
- `/zones/climate-risk` 继续作为监管知识专区，只展示事件、地区里程碑、法规标准与风险来源；不得嵌入实验室主体。
- 以影响链和经营条件对比为中心；只使用一个虚拟项目，坐标和现场人数在“项目现状”中展开。空间数据未接入时不展示假热区或伪厂界。
- IPCC AR6/CMIP6提供SSP1-2.6、SSP2-4.5、SSP5-8.5；IEA WEO2025提供CPS、STEPS、NZE；NGFS Phase V首期选三条转型路径。三类体系可切换但不自动一一映射；情景版本和用途持续可见。
- 所有数值必须展示来源、版本、空间分辨率、基准期、观察期和不确定性区间；无法提供时明确标为示意。
- 来源数据、资产输入与用户压力测试假设必须分层显示。年均降水、湿度等观测或模型基准不得被界面改写；用户只能增加明确标记的偏移量。
- 删除统一情景乘数和任意环境权重。阶段A按用户假设计算单次冲击（停工天数×每日贡献毛利+修复支出）或年度增量碳成本；显示适应投入与避免停工损失。阶段B按经验证数据计算当地气候指标；无数据时明确待接入。
- 公允价值仅解释市场参与者假设、现金流、风险溢价、资产寿命和残值等可能传导，不输出“AI 公允价值”。
- 会计影响同时覆盖适用的 IFRS 13、公允价值计量，IAS 36 减值，以及在特定事实下可能涉及的 IFRS 9、IFRS 17、预计负债和折旧估计；不得暗示所有气候风险都通过公允价值反映。
- 相关事件采用滚动五年窗口，优先采集企业年报、公司公告、证券监管申报和执法机构材料；必须记录事件发生日、企业、风险类型、直接影响、量化影响、证据等级和归因边界。
- 案例默认按风险相关性排序，并支持按影响程度和发生时间排序。影响程度采用企业重要性分档，不直接以未经统一口径处理的跨币种名义金额排名。
- 事件影响与气候变化归因必须分开：只有权威归因研究支持时才能标记气候归因，否则仅表述为气候相关物理危险或转型风险事件。
- 模块必须持续显示“非预测、非工程评估、非保险定价、非法定估值”的用途边界。

#### 验收标准

- 桌面端与 390px 移动端无横向溢出，键盘焦点和语义角色可用。
- 修改风险和情景后，适用解释、版本和案例同步变化；用户经营假设独立保留。坐标未接数据前不应导致数值变化。
- 所有可调参数均能恢复默认值；压力测试偏移不得覆盖或伪装成原始来源数据。
- 所有三类情景体系可选；体系变更时自动选择适用风险，保留各体系路径偏好。IEA/NGFS未接定量路径时不得改变用户数值冒充官方输出。
- 企业案例按滚动五年与发生日筛选，含风险影响、适应与恢复、商业机遇；缺少高相关证据时显示空状态，不要求填满每种风险。
- 生产数据上线前，所有示意值均有显著标识，且不得写入公开内容 API 作为事实数据。
- 客户端不加载或计算 NetCDF/GeoTIFF；交互数据应由服务端预计算为轻量 JSON/矢量瓦片。

#### 成功指标与护栏

- 主要指标：进入模块的用户完成至少一次“地点 + 风险”组合查看的比例。
- 次要指标：情景切换率、相关事件点击率、完整影响链到达率。
- 质量指标：来源与版本字段完整率 100%，示意数据误认反馈为 0。
- 护栏：气候风险专区首屏性能不得因大型原始栅格下降；不得把模型结果表述为厂界测量或确定性损失。

#### 当前不在范围

- 企业档案、资产组合管理、自动风险预警和企业风险排名。
- 将实验室与气候法规地图合并为同一详情页。
- 上传完整资产清单、实时灾害预警、精确厂址损失估计和工程防灾设计。
- 任意多边形厂界绘制、栅格相交和面积加权；完成数据许可与空间计算验证前只支持点位加分析半径。
- 代替估值师、精算师或审计人员形成法定结论。
- 在未解决许可前复制或再分发 IEA 受限数据产品。

实施依赖、计算边界、证据规范和阶段验收以[气候实验室技术方案](CLIMATE_LAB_TECHNICAL_PLAN.md)为准。

阶段B目标限定上海、鹿特丹两个参考网格及三条SSP；当前部分预览仅上海SSP1-2.6/SSP2-4.5完整，其他组合因NASA服务故障未验收。使用NASA NEX-GDDP-CMIP6 v2.0 / ACCESS-CM2 / r1i1p1f1 / tasmax，比较1995–2014与2041–2060。默认高温展示严格超过35°C的年均天数、变化和未来20个逐年计数；35°C是教学阈值，不是劳动安全或停工阈值。历史值也是模型模拟，不应标成观测值。单模型不显示集合置信区间。其他地点、情景或时间窗保持缺数据状态，不扩大覆盖范围。原始CSV、请求地址、校验哈希与实际网格坐标须可复算。背景跟踪图与企业持续采集仍待后续交付。

## 5. Prompt 治理

- Prompt 存放于 `prompts/*.md`，业务规则不散落在调用代码中。
- 模板只允许两种语法：
  - `{{name}}`：调用方提供的变量。
  - `{{> file}}`：递归插入另一个 Prompt 文件。
- 缺变量、缺文件和 include 循环必须显式抛错，不得替换为空字符串。
- `promptVersion` 必须包含入口文件及全部 include 文件内容的哈希。
- 每次运行写入 `promptVersions`，发布版本可用于审计。
- 材料内容始终是不可信数据；材料中的命令、答题要求或输出格式不得被执行。

## 6. 非功能需求

### NFR-01 可复现

- 快照模式在相同输入、相同代码和相同时钟下应生成稳定内容、故事和状态。
- 时间相关值允许 `generatedAt` 变化，但排序和选择必须确定。

### NFR-02 可测试

- 预筛、评分、聚簇、热度、Prompt、发布存储必须有聚焦测试。
- 测试不得依赖真实网络、真实模型密钥或生产数据写入。

### NFR-03 可维护

- 类型契约集中在 `lib/contracts`。
- 流水线步骤彼此独立，入口只负责编排和持久化。
- API 与页面不重复实现内容读取规则。

### NFR-04 性能

- 公开页面只读取本地发布快照，不触发采集或模型调用。
- 内容 API 单页最多返回 50 条。
- 首页支持按月份过滤，不要求一次渲染完整历史。

### NFR-05 科学可追溯性

- 每个气候指标保留数据提供方、数据集、版本、变量、情景、基准期、观察期、空间分辨率、统计量和生成时间。
- 模型集合优先展示中位数及 P10/P90 或等价区间，不以单一模型值伪装确定性。
- 数据源更新后通过版本化缓存重算，不静默覆盖历史结果。

v2 完成必须满足：

1. `npm run pipeline` 能从快照生成 `data/publication`。
2. `npm run typecheck` 无错误。
3. `npm test` 全部通过。
4. `npm run build` 成功。
5. 首页、事件、专区和运营页面可从发布快照正常读取。
6. 内容 API 无旧 Agent 命名，鉴权、分页和过滤可验证。
7. 产品地图、路线图与本文档均不包含已删除功能。
8. 气候风险原型在桌面和移动端可用，物理与转型情景分离，所有示意值和用途边界清晰可见。
