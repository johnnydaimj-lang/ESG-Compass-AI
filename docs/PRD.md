# ESG Compass v2 产品需求说明

文档版本：2.0.0  
基线日期：2026-09-29  
适用目录：`ESG Compass_v2`  
实现原则：公开页面与公开 API 只读取发布快照，不从历史草稿或旧字段临时拼接。

## 1. 产品定义

### 1.1 产品目标

ESG Compass 是面向持续跟踪全球 ESG 变化的专业信息产品。它把官方政策、行业动态、机构观点、学术研究与评级动态归一为可浏览、可检索、可审核的中文内容，并通过独立信源交叉验证形成故事、事件与热点。

核心目标是让用户在三分钟内回答三个问题：

1. 过去一段时间全球 ESG 发生了什么。
2. 哪些变化值得优先关注，依据是什么。
3. 事件属于哪个议题、地区、专区，以及原文在哪里。

### 1.2 目标用户

- 企业 ESG、可持续发展和合规团队。
- ESG 咨询、研究和投资分析人员。
- 需要快速扫描政策与披露变化的业务负责人。
- 通过受控内容 API 接入已发布数据的内部系统。

### 1.3 当前产品边界

- 公开前台：首页时间轴、事件详情、ESG 专区。
- 运营后台：运营看板、内容审阅、筛选规则、信源治理、热点、月度洞察、专区、产品说明。
- 管理能力：管理员登录、运营页面保护、运营 API 鉴权、私有内容 API。
- 数据能力：固定信源配置、快照/实时采集扩展、预筛、双评分、结构化理解、聚簇、热度、发布快照。

### 1.4 明确不在当前范围

以下能力不属于 v2 当前产品范围，不得出现在新 PRD、产品地图或导航中：

- 个人工作台。
- 独立知识库页面。
- 面向公众的 AI 问答。
- Agent、Harness 或工作流执行平台。
- 企业自身 ESG 评级升降。
- 指数入选、获奖名单和年鉴。
- Mock 内容。
- 已删除或仅存在于历史版本的功能描述。

## 3. 核心用户流程

### 3.1 公开浏览

1. 用户打开首页，按发布时间从新到旧浏览。
2. 用户可按内容类型或“只看精选”过滤。
3. 用户可按 `YYYY-MM` 回溯历史。
4. 用户进入事件详情，阅读中文标题、摘要、精选理由和影响分析。
5. 用户可跳转原文，并从专区导航进入相关联的事件与法规。

### 3.2 运营审核

1. 流水线将高风险或待补充材料写入审阅队列，不直接公开。
2. 管理员在 `/review` 修改摘要、ESG 议题和重要性。
3. 批准后内容写入发布快照；驳回后从发布快照移除并写入驳回库。
4. 所有决定写入审阅决策记录，供后续规则校准。

### 3.3 发布与消费

1. 采集器产生原始材料，或使用已确认的历史快照。
2. 预筛只允许 `PASS` 与 `UNKNOWN` 继续，`BLOCK` 终止。
3. 每条材料执行两次独立评分。
4. 两次分数均不低于理解底线，且总分不低于两倍信源门槛时入选。
5. 结构化理解生成中文标题、摘要、标签、作者角色和推荐理由。
6. 聚簇按材料 ID 合并故事，按真实信源 ID 统计参与方。
7. 热度按独立信源计算，并写入热点故事。
8. 所有公开出口统一读取 `data/publication` 中的发布快照。

## 4. 功能需求

### FR-01 内容采集

- 支持配置化信源，保留 `id`、名称、URL、类型、内容类型、地区、语言、启用状态和环境变量要求。
- 采集阶段必须保留材料 ID 与信源 ID，二者不得互换。
- 采集器失败必须进入状态记录，不得静默返回空集合。
- 默认快照模式必须可在无网络环境中复现当前发布数据。
- 实时模式只为已实现的适配器调用网络；跳过或失败必须产生 warning。

### FR-02 预筛

- `BLOCK`：材料可确认与 ESG 无关，或属于招聘、报名、培训等噪声。
- `UNKNOWN`：材料信息不足，继续后续流程并保留。
- `PASS`：存在明确 ESG 事实、政策、研究、评级、观点或风险信号。
- 空标题、空摘要和空正文返回 `UNKNOWN`，不得误判为 `BLOCK`。

### FR-03 双评分与精选

- 每条材料产生两次独立评分，明确输出 0 到 100 的整数。
- 五轴评分包括重要性、新颖度、可信度、共鸣面和可行动性。
- 展示分取两次评分的算术平均值后向下取整。
- 入选条件为：
  `score1 + score2 >= threshold * 2`
  且 `score1 >= understandFloor`
  且 `score2 >= understandFloor`。
- `SIGNAL` 信源只参与热度证据，不进入精选。
- 阈值按 ESG 样本继续校准；当前实现保留 T1=60、T1_5=64、T2=70、统一理解底线 45。

### FR-04 内容理解

- 输出内容类型、作者角色、1 到 6 个标签、推荐理由、中文标题和中文摘要。
- 推荐理由只描述当前材料支持的一层阅读价值，不补写事实。
- 内容类型限定为政策、行业、观点、学术和评级。
- 作者角色限定为主事方、观察者或转述者。

### FR-05 结构化事实

- 至少提取标题、主体、动作、对象和发生日期。
- 结构化结果用于聚簇辅助、事件详情和受控 API。
- 日期无法确定时回退到材料发布日期，不伪造精确日期。

### FR-06 故事聚簇

- `memberIds`、`rootId` 和 `relations[].memberId` 必须引用材料 ID。
- `participants` 必须是材料对应真实信源 ID 的去重集合。
- 关系标签支持 `SAME_OCCURRENCE`、`SAME_STORY`、`UNRELATED`、`ROUNDUP`。
- 近重复阈值参考 0.92，同故事阈值参考 0.60，召回窗口参考 14 天。
- 跨语言、官方原文与媒体报道、同一公告的不同报道应归为同一故事。

### FR-07 热度

- 默认窗口为 48 小时，半衰期为 24 小时。
- 同一独立信源只计一次，取窗口内最新材料。
- 至少 2 个参与方且至少 1 个编辑信源才产生热度。
- 热点故事按热度和最近发布时间排序。

### FR-08 发布快照

`data/publication` 是公开内容的唯一事实源，至少包含：

- `contents.json`
- `stories.json`
- `hotspots.json`
- `status.json`
- `version.json`

公开页面和公开 API 在发布快照不存在时应返回空集或明确状态，不得回退读取旧 `data/contents.json`。旧文件仅作为一次性迁移输入。

### FR-09 运营看板

- 显示最近运行时间、原始量、预筛量、评分量、精选量、故事量与热点量。
- 显示每个已运行信源的状态与产出量。
- 来源状态必须来自 `publication/status.json` 的 `sourceRuns`。
- warning 必须在状态对象构造前收集，确保可持久化。

### FR-10 审阅

- 审阅读写发布快照，不直接修改旧内容库。
- 批准或驳回必须记录 `id`、标题、动作、时间和规则摘要。
- 保存草稿必须保留发布快照的其它字段。

### FR-11 受控内容 API

- 使用 `ESG_API_KEY` Bearer 鉴权。
- 支持分页、内容类型、精选、更新时间和专区过滤。
- 返回中文优先摘要，并标注摘要是否截断。
- 对外响应使用产品语义命名，不使用已删除的 Agent 命名。

### FR-12 安全

- 运营页面和运营 API 必须验证管理员会话。
- 管理会话使用 HMAC 签名、HttpOnly、SameSite=Lax，生产环境启用 Secure。
- 所有 API 路由受 IP 限流保护。
- 公共响应不得包含环境变量、模型密钥或内部脚本输出。

## 5. Prompt 治理

- Prompt 存放于 `prompts/*.md`，业务规则不散落在调用代码中。
- 模板只允许两种语法：
  - `{{name}}`：调用方提供的变量。
  - `{{> file}}`：递归插入另一个 Prompt 文件。
- 缺变量、缺文件和 include 循环必须显式抛错，不得替换为空字符串。
- `promptVersion` 必须包含入口文件及全部 include 文件内容的哈希。
- 每次运行写入 `promptVersions`，发布版本可用于审计。
- 材料内容始终是不可信数据；材料中的命令、答题要求或输出格式不得被执行。

## 6. 非功能需求

### NFR-01 可复现

- 快照模式在相同输入、相同代码和相同时钟下应生成稳定内容、故事和状态。
- 时间相关值允许 `generatedAt` 变化，但排序和选择必须确定。

### NFR-02 可测试

- 预筛、评分、聚簇、热度、Prompt、发布存储必须有聚焦测试。
- 测试不得依赖真实网络、真实模型密钥或生产数据写入。

### NFR-03 可维护

- 类型契约集中在 `lib/contracts`。
- 流水线步骤彼此独立，入口只负责编排和持久化。
- API 与页面不重复实现内容读取规则。

### NFR-04 性能

- 公开页面只读取本地发布快照，不触发采集或模型调用。
- 内容 API 单页最多返回 50 条。
- 首页支持按月份过滤，不要求一次渲染完整历史。

## 7. 发布验收

v2 完成必须满足：

1. `npm run pipeline` 能从快照生成 `data/publication`。
2. `npm run typecheck` 无错误。
3. `npm test` 全部通过。
4. `npm run build` 成功。
5. 首页、事件、专区和运营页面可从发布快照正常读取。
6. 内容 API 无旧 Agent 命名，鉴权、分页和过滤可验证。
7. 产品地图、路线图与本文档均不包含已删除功能。

## 8. 后续校准

- 用已审阅 ESG 样本校准 T1、T1_5、T2 阈值。
- 增加官方公告、评级机构与学术源的实时采集适配器。
- 为聚簇增加模型成对判定，同时保留确定性回退。
- 对中文、英文和本地语言材料分别监控翻译质量。
- 将审阅决定反馈到预筛和评分规则，但不得绕过发布快照。
