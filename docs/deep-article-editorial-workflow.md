# 观澜 ESG Compass 深度文章工作流

版本：v2  
适用范围：微信公众号周报、热点与争议解读、专业研究分析  
运行模式：员工 1 号筛选产品内容，员工 2 号自主选题和加工，Johnny 选题并终审

## 1. 工作流解决什么问题

周报回答“本周发生了什么”。深度文章回答“为什么值得关注、机制是什么、对谁有影响、哪些
解释不成立、接下来看什么”。

新的产品分工不是把周报信号直接交给员工 2 号，而是让员工 2 号直接读取 ESG Compass 的
产品内容，自主寻找：

- 值得回应的热点和争议。
- 有代表性的企业、行业或项目案例。
- 重要政策及其执行机制。
- 有价值的研究报告、数据或方法。

这样，员工 1 号负责降低信息噪声，员工 2 号负责把有潜力的信息加工成有判断的深度内容。

## 2. 三条公众号内容线

| 内容线 | 读者价值 | 核心要求 | 运营作用 |
| --- | --- | --- | --- |
| 周报 | 快速了解一周重要变化 | 稳定、可扫描、事实清楚 | 维持更新频率和用户习惯 |
| 热点与争议 | 理解争议背后的机制和立场 | 有传播窗口、有证据、有观点、多方回应 | 获取新读者和讨论度 |
| 专业研究 | 理解政策、报告、数据和方法 | 有机制、有边界、有独立判断 | 建立专业可信度 |

### 2.1 周报

- W43 已由 Johnny 人工发布。
- 周报继续使用既有制作、审批和发布流程。
- 员工 2 号不消费旧周报信号，也不将周报汇总当作深度文章候选池。
- 如果某个周报事件值得深挖，员工 2 号必须从 ESG Compass 产品内容和原文重新建立证据链。

### 2.2 热点与争议

适合选题：

- 诉讼、投诉、调查、处罚、召回和监管质询。
- 漂绿、误导性宣传、数据争议和利益冲突。
- 企业承诺与实际结果的反差。
- 多个来源共同关注、热度快速上升的故事。
- 有明确公共影响、但常见报道只停留在表面的案例。

可以“蹭热点”，但不能“造热点”。文章的价值来自解释机制和提供判断，不是放大情绪。

### 2.3 专业研究

适合选题：

- 新政策、规则、标准和执行细则。
- 有方法或数据增量的研究报告。
- 行业口径、监管口径或市场数据的变化。
- 一个流行结论背后的证据边界。

专业文章不能只有摘要。至少要回答：

- 这项政策或研究改变了什么判断。
- 哪些主体会改变行为。
- 哪些结论仍不能证明。
- 接下来用什么数据验证。

## 3. 角色分工

| 主体 | 主要职责 | 产出 | 不做什么 |
| --- | --- | --- | --- |
| 员工 1 号：内容筛选者 | 维护 ESG Compass 产品内容、来源、聚簇、热度和趋势索引 | 产品内容、只读选题扫描 | 不替 Johnny 选题，不写终稿 |
| 员工 2 号：内容加工者 | 自主浏览产品、提出候选、研究取证、写作和自检 | topics、drafts、reviews | 不自行终审，不发布 |
| Johnny：主编 | 决定选题，润色观点和标题，核对高风险事实，批准发布 | 选题决定、终审意见、发布批准 | 不把责任外包给自动化 |
| 发布链路 | 排版、封面、摘要、草稿、定时发表 | 发布记录 | 不改观点，不跳过审批 |

角色分离规则：

- 员工 2 号不能批准自己的稿件。
- AI 自检不能写成 Johnny 的终审结论。
- 产品摘要、热度、编辑标签都不能当作公开事实。
- 发布自动化只能消费 Johnny 已批准且内容哈希一致的版本。

```text

        |
        v

        |

        |
        v

        |
        v

        |
        v
既有排版和微信公众号发布链路

```

## 5. 阶段 1：产品扫描与选题候选

员工 2 号在工作目录执行：

```powershell
cd "D:\学习\ESG智能体\ESG Compass AI\ESG Compass_v2"
npm.cmd run contentops:product-read -- --days=30 --limit=40 --format=json
```

需要人类可读结果时：

```powershell
npm.cmd run contentops:product-read -- --days=30 --limit=40 --format=markdown
```

默认排除周报汇总。只有 Johnny 明确要求时才使用 `--include-weekly`。

选题时优先看：

- `opportunityHints` 中的争议、漂绿、监管、案例和研究线索。
- `storySourceNames` 显示跨来源聚合的故事。
- `storyHeat`、`storyTrend` 显示正在升温的故事。
- 不同来源对同一事件的表述差异。
- 政策阶段、数字口径或企业行动中尚未被解释清楚的部分。

每轮输出 2-3 个候选到：

```text
data/content-ops/topics/{candidateKey}.json
```

候选必须回答：

```text
我们认为：[表面事件]
真正意味着：[机制或结构性变化]
对 [目标读者] 的影响是：[具体影响]
接下来最重要的观察指标是：[一个或两个信号]
```

候选字段：

```json
{
  "candidateKey": "2026-w44-example",
  "status": "shortlisted",
  "editorialLine": "hotspot",
  "workingTitle": "暂定标题",
  "productItemIds": ["content-id"],
  "storyIds": ["story-id"],
  "sourceUrls": ["https://..."],
  "eventFact": "已经确认发生了什么",
  "controversy": "真正需要解释的争议或机制",
  "thesis": "一句话判断",
  "whyNow": "为什么现在",
  "targetReader": "目标读者",
  "evidenceAvailable": ["已有的一手证据"],
  "evidenceGaps": ["缺失的证据"],
  "riskLevel": "medium",
  "risks": ["名誉或合规风险"],
  "scores": {
    "timeliness": 0,
    "relevance": 0,
    "informationGain": 0,
    "originality": 0,
    "evidenceAvailability": 0,
    "actionability": 0,
    "total": 0
  },
  "createdAt": "ISO 时间",
  "updatedAt": "ISO 时间"
}
```

退出条件：

- 有明确发生时间和原文链接。
- 能说清为什么现在。
- 能写出目标读者和一句话判断。
- 没有把产品摘要当作事实。

## 6. 阶段 2：Johnny 选题

Johnny 只判断四个问题：

1. 为什么现在值得写。
2. 读者能获得什么新判断。
3. 现有报道漏掉了什么机制、利益相关方或证据。
4. 一周内能否获得足够证据。

选题决定至少包括：

- 文章类型：hotspot 或 research。
- 目标读者。
- 一句话判断。
- 可以写的范围。
- 不能越过的边界。
- 交付时间和发布窗口。

员工 2 号不得自行将候选标为 selected，不得提前写完整稿等待选题。

## 7. 阶段 3：研究和证据

研究包目录：

```text
data/content-ops/drafts/{candidateKey}/
  01-research.md
  02-source-map.json
  03-outline.md
  04-draft-v1.md
  05-self-check.md
  06-open-issues.md
```

### 7.1 必答问题

- 事件时间线：发生、提出、通过、生效、过渡、执行。
- 关键主体：监管者、企业、中间机构、受影响群体和反对者。
- 机制：规则或事件如何改变行为、成本、信息或责任。
- 数字：口径、期间、单位、地域、样本和计算方法。
- 反方：至少两条削弱核心判断的材料或竞争解释。
- 未知：明确列出，不能用推测填空。

### 7.2 热点与争议专用

- 区分指控、投诉、调查、裁决、处罚和已执行结果。
- 将被指控方回应放入正文，而不是只在脚注列出。
- 同一稿件被多家媒体转载，不视为多个独立来源。
- 不用匿名爆料替代可核验材料。
- 不把“没有回应”写成“默认承认”。

### 7.3 政策专用

- 找到规则原文和官方发布页。
- 明确适用主体、地域、业务范围和法律效力。
- 区分提案、通过、生效、过渡期和执行。
- 找到执行机关和违反后果。
- 说明企业最容易误读的条款。

### 7.4 研究报告专用

- 找到报告原文，不只读新闻稿。
- 记录样本、方法、数据期间、资助方和利益关系。
- 区分报告发现、作者解释和媒体标题。
- 说明哪些结论不能外推。
- 与既有研究或数据交叉验证。

### 7.5 来源分级

| 等级 | 来源 | 使用规则 |
| --- | --- | --- |
| A | 法律法规、监管公告、司法文书、企业公告和财报、官方统计、同行评审论文、报告原文 | 支撑关键事实 |
| B | 专业媒体、行业协会、机构摘要、专家公开评论 | 补充背景；争议事实需补 A 级原件 |
| C | 社交媒体、博客、聚合新闻、二手转述 | 只作线索 |

退出条件：

- 核心事实有 A 级来源。
- 争议文章有多方材料。
- 来源矩阵中的每条来源有链接、日期、定位符和支持内容。
- 找不到关键证据时已经降级或停止。

## 8. 阶段 4：判断链大纲

推荐结构：

1. 一个具体场景、数字、条款或反差。
2. 为什么现在发生。
3. 机制：变化到底改变了什么。
4. 证据：谁受影响，影响如何发生。
5. 反方与边界：哪些解释不成立，哪些仍不确定。
6. 对读者和企业的含义。
7. 接下来观察什么。

每个一级小节写清：

- 本节要证明什么。
- 使用哪些来源。
- 缺少证据时如何降级。
- 与核心判断的关系。

退回大纲的情况：

- 标题有观点，正文没有证据链。
- 两节都在交代背景。
- 只是资料堆叠，没有递进。
- 只总结报告，没有解释意义。
- 用“重大、深远、全面”代替机制。

## 9. 阶段 5：初稿

写作规则：

- 每个事实句带 `[S#]`。
- 事实、解释和观点分段。
- 段落只承担一个论证任务。
- 不用“行业普遍认为”“专家表示”“数据显示”掩盖来源缺失。
- 标题、导语和结论表达同一强度的判断。
- 观点使用“我们的判断是”“更合理的解释可能是”等可识别表达。
- 不用形容词替代机制。

观点标准：

- 热点文章要有立场，但必须承认事实边界和反方解释。
- 专业文章要有判断，但不能把政策意图、研究假设或相关性写成已证实结果。
- 立场不能建立在贬低中国、抹黑中国制度或政策、损害中国整体形象之上。

## 10. 阶段 6：自检和合规审阅

事实检查：

| 检查项 | 通过标准 |
| --- | --- |
| 核心事实 | 原文直接支持 |
| 政策阶段 | 提案、通过、生效、过渡、执行没有混写 |
| 数字 | 来源、口径、期间、单位、地域一致 |
| 引语 | 可核验，保留语境 |
| 公司表述 | 目标、承诺、行动、结果分开 |
| 因果 | 没有把相关写成因果 |
| 标题 | 没有强于正文证据 |
| 来源 | 关键事实有 A 级来源 |

合规检查：

| 检查项 | 通过标准 |
| --- | --- |
| 名誉 | 没有无来源指控、人身攻击或暗示性定罪 |
| 隐私 | 没有个人隐私、内部材料或未公开商业信息 |
| 争议公平 | 有对方回应和证据边界 |
| 平台规则 | 没有仇恨、歧视、恐慌、虚假对立或阴谋叙事 |
| 中国相关内容 | 不贬低中国，不抹黑中国制度或政策，不把个案上升为整体否定 |
| 发布边界 | 没有任何真实微信发布动作 |

所有阻断项写入 `06-open-issues.md`。员工 2 号只能提出自检结论，不能代替 Johnny 终审。

## 11. 阶段 7：交给 Johnny

待审稿目录：

```text
data/content-ops/reviews/{candidateKey}/
  README.md
  draft-final-candidate.md
  source-map.json
  fact-check.md
  open-issues.md
```

交接只写：

1. 核心判断。
2. 为什么现在。
3. 已核实的关键事实。
4. 未解决的事实、合规、名誉或措辞风险。
5. Johnny 需要做的具体决定。

Johnny 审阅：

- 文章是否值得现在发。
- 判断是否被证据支持。
- 标题、导语和结论是否诚实一致。
- 最可能被质疑的地方是否已经处理。
- 是否存在政治、平台、名誉或隐私风险。

## 12. 阶段 8：发布和复盘

只有 Johnny 明确批准后，才进入既有发布链路。

发布包至少包括：

- 标题和摘要。
- 作者、编辑和审核人。
- 正文最终版。
- 来源列表。
- 封面和图表说明。
- 内容哈希。
- 审批人和审批时间。
- 计划发布时间。
- 风险和更正联系人。

标题、正文、来源、图表或时间变化，旧审批失效并要求重新审批。

发布后记录：

- 打开、读完、分享、收藏和来源点击。
- 读者提出的新问题、误解和反对意见。
- 是否需要更正。
- 哪类选题真正建立了专业识别度。

复盘的目标不是单纯追阅读量，而是判断筛选、选题、证据和表达是否有效。

## 13. 选题评分

| 维度 | 分值 | 判断 |
| --- | --- | --- |
| 时机性 | 20 | 正在发生或临近节点 |
| 读者相关性 | 20 | 连接企业决策、风险或理解需求 |
| 信息增量 | 20 | 增加机制、数据、反方或时间线 |
| 角度独特性 | 15 | 有具体反差或新解释 |
| 证据可得性 | 15 | 一周内能获得足够 A/B 级来源 |
| 可行动性 | 10 | 能给出观察指标或决策含义 |

低于 70 分不进入正式研究。事实阻断项不能被高分抵消。

## 15. 一键验收

员工 2 号交付时自查：

- `topics/` 中是否有 2-3 个候选。
- 每个候选是否有产品来源和原文链接。
- 是否等待 Johnny 明确选题。
- `drafts/` 是否有完整研究包。
- 关键事实是否有 A 级来源。
- 争议是否有对方回应。
- 标题是否强于证据。
- 是否有政治和平台合规风险。
- `reviews/` 是否能让 Johnny 独立审阅。
- 是否绝对没有真实发布动作。

Johnny 最终只看三件事：这篇文章是否值得现在发、判断是否被证据支持、风险是否已经被
说清楚。三者缺一，不进入发布链路。
